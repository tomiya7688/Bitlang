# static と Direct

この文書は、Bitlang source における `static` と `Direct` 修飾子の規則を定義する。

次の言語設計 Issue を閉じる内容である。

- [#1 `static` を「静的保持」の意味に統一する](https://github.com/tomiya7688/Bitlang/issues/1)
- [#2 「インスタンス不要」を表す専用修飾子を定義する](https://github.com/tomiya7688/Bitlang/issues/2)

## 定義

### `static`

> `static` は、対象が通常のローカル寿命やインスタンス寿命とは独立した静的保持領域に存在し、その領域が有効な間、情報・状態を保持することを示す修飾子である。

- `static` は **「インスタンス不要」を意味しない**。
- 適用可能な対象種別（変数・関数・型メンバなど）では、同じ基本意味を持つ。

### `Direct`

> `Direct` は、対象へアクセスまたは呼び出すためにインスタンスを要求しないことを示す修飾子である。寿命・保持性・初期化方式にはそれ自体では影響しない。

- 正式キーワードは `Direct` である。
- `Direct` は `static` と完全に独立（直交）する。

## 4つの直交状態

両方の修飾子が適用可能な対象では、次の4組み合わせを **構文上すべて許可** する。

| static | Direct | 意味 |
| --- | --- | --- |
| なし | なし | 通常のインスタンス依存対象 |
| あり | なし | 静的保持だが、アクセスにはインスタンスが必要 |
| なし | あり | インスタンス不要だが静的保持ではない |
| あり | あり | 静的保持かつインスタンス不要 |

### 方針

> 4状態はすべて構文上許可する。プリプロセッサおよび後続の静的解析は、対象種別・文脈・寿命・所有権・借用状態などと組み合わせたときに意味論上の矛盾や不正なアクセス経路が生じないことを検証しなければならない。検証に失敗した場合は、黙って受理せず診断（error または warning）を出す。

## 対象別適用規則

### 関数

| 種類 | static | Direct |
| --- | --- | --- |
| 型メンバ関数 | 可 | 可（4状態すべて構文許可） |
| フリー関数 | 可 | **不可**（`Direct` は error） |
| ローカル関数 | 可 | **不可**（`Direct` は error） |

型メンバ関数の意味:

| static | Direct | 意味 |
| --- | --- | --- |
| なし | なし | 通常のインスタンスメソッド。レシーバ必須 |
| あり | なし | 静的保持を持つが、呼び出しにはインスタンスが必要 |
| なし | あり | インスタンスなしで呼べる。呼び出しをまたぐ静的保持はない |
| あり | あり | インスタンスなしで呼べ、かつ静的保持を持つ |

### 変数

| 種類 | static | Direct |
| --- | --- | --- |
| 型メンバ変数 | 可 | 可（4状態すべて構文許可） |
| ローカル変数 | 可 | **不可**（`Direct` は error） |
| パラメータ | **不可** | **不可**（両方 error） |

型メンバ変数の意味:

| static | Direct | 意味 |
| --- | --- | --- |
| なし | なし | 通常のインスタンスフィールド |
| あり | なし | 静的保持フィールドだが、アクセスにはインスタンスが必要 |
| なし | あり | インスタンスなしで参照可能。ただし静的保持ではない |
| あり | あり | インスタンスなしで参照可能、かつ静的保持 |

### モジュールレベル宣言

| 対象 | static | Direct |
| --- | --- | --- |
| モジュールレベル関数 | 可 | 原則として **意味をなさない**（既定は warning。設定で error 昇格可） |
| モジュールレベル変数 | 可 | 原則として **意味をなさない**（同上） |

理由: module はインスタンスを持たないため、`Direct` は意味を追加しない。モジュール寿命を超える静的保持が必要な場合の `static` は有効である。

### 継承 / override / interface

- `static` の有無は契約の一部である
- `Direct` の有無は契約の一部である
- override でこれらの有無を変更してはならない
- interface 実装は、interface が要求する修飾子契約を満たさなければならない

## プリプロセッサの検証義務

検証の優先順位:

1. **適用対象外** → error  
   （例: ローカルへの `Direct`、パラメータへの `static` / `Direct`）

2. **契約違反** → error  
   （override または interface での `static` / `Direct` 不一致）

3. **アクセス経路の矛盾** → error  
   （例: `Direct` なし対象をインスタンスなし経路から操作する）

4. **寿命・所有権・借用との衝突** → error または warning  
   （証明可能な不正は error、証明不能な危険は warning）

5. **冗長指定** → warning  
   （例: モジュールレベル `Direct`）

**禁止**: 矛盾や危険な組み合わせを silent に受理すること。

代表的な確認項目:

- `Direct` なしの関数・メンバを、インスタンスなし経路から呼び出していないか / 参照していないか
- `Direct` あり関数が、暗黙のレシーバ / `this` に依存していないか
- `static` なし `Direct` あり関数が、静的保持であるかのように呼び出しをまたぐ状態を持とうとしていないか
- override / interface 実装で `static` と `Direct` の契約が一致しているか
- アクセス経路が所有権・借用状態・移動状態・解放状態と矛盾していないか
- モジュールレベル `Direct` を冗長として診断しているか（将来の module-instance モデルが明示的に意味を与える場合を除く）

## 実装者向け要約

```text
static と Direct は独立した修飾子である。
static は静的保持のみを示し、Direct はインスタンス不要のみを示す。

関数（型メンバ）と変数（型メンバ）では、static と Direct の
4組み合わせを構文上許可する。

フリー関数、ローカル関数、ローカル変数では Direct を許可しない。
パラメータでは static も Direct も許可しない。

モジュールレベル宣言では Direct は原則として冗長であり、
診断対象とする。

override および interface 実装では、static と Direct の
有無は契約の一部であり、変更してはならない。

プリプロセッサは、上記の組み合わせが寿命・所有権・借用・
アクセス経路と矛盾しないことを検証する。
証明可能な不正は error、証明不能な危険は warning とし、
黙って受理してはならない。
```

- destructor 相当の終了処理との関係
- Bitlang Preprocessed / Compiled における `static` と `Direct` の具体表現
- 将来の module-instance モデルがモジュールレベル `Direct` に意味を与えるかどうか
- static 対象の初期化順序の詳細規則
